# 행사·사업 랜딩페이지 만들기

## 시작과 카드 진행

스킬 개발 요청이면 개발을 수행한다. 실제 페이지 제작 요청이면 아래 여정을 한 번 안내하고 현재 필요한 카드 한 장을 연다.

> 자료 받기 → 페이지 구성 정하기 → 디자인·움직임 고르기 → 첫 화면 비교하기 → 전체 페이지 채우기 → PC·모바일 확인하기 → 공개하기
>
> 행사 계획안이나 사업 공고문, 키비주얼·포스터·기관 로고, 마음에 드는 사이트 주소를 가진 것부터 보내주세요. 연사 사진·기업 명단·최종 신청 링크는 나중에 넣어도 됩니다.

[단계별 카드](references/cards.md)를 읽고 시작한다. 이미 준 자료는 먼저 읽어 “이렇게 읽었습니다” 요약으로 보여주고 틀린 부분만 받는다. 초기 카드에서 모든 자료를 요구하지 않는다. 파일이 없으면 간단한 설명으로 시작한다. 미확정 내용을 사실처럼 채우지 않고 공개예정·추후 확정 등 적절한 표기를 제안한다.

카드는 제목, 현재 단계, 이미 파악한 내용, 필요한 선택 또는 자료, 이번 단계의 결과로 구성한다. 선택지는 사용자가 이해할 말로 쓰고 직접 수정도 받는다. 가능한 질문 도구로 텍스트 선택을 받는다. request_user_input_async에는 파일 업로드·스크린샷 전송을 요청하지 않는다. 파일·URL 전달 안내는 일반 채팅에 표시한다. 도구가 없으면 Markdown 카드와 번호 선택으로 진행한다. 별도 업로드 UI가 있는 것처럼 말하지 않는다.

한 카드의 여러 입력을 작은 질문으로 나눌 수 있다. 질문 도구의 개수 제한을 지킨다. 이미 답한 질문, 자료에서 알 수 있는 질문, 결과를 바꾸지 않는 질문은 생략한다. 사용자가 추천에 맡기면 자료에 맞는 안으로 진행하고 채택한 기본값을 짧게 알린다. 선택이 필요한 시안은 실제 이미지나 작동하는 미리보기를 먼저 보여준다. 로컬 이미지의 Markdown 경로는 절대경로로 표시한다. 웹 링크와 출력 파일은 사용자가 열 수 있는 실제 대상으로 연결하고, 표시 경로와 파일 존재 여부를 확인한 뒤 선택을 받는다.

## 제작 원칙

- 목적·대표 행동·콘텐츠 관계부터 정한 뒤 디자인을 선택한다. 행사에는 프로그램·연사·장소, 사업에는 대상·혜택·기간·방법을 제안하고 실제 자료에 맞춰 조정한다.
- 참고 URL은 실제 열어 구조·색감·타이포그래피·움직임 중 무엇을 참고할지 확인한다. 접속 실패 시 캡처나 설명을 받고 확인 범위를 밝힌다.
- 키비주얼이 없으면 로고와 주제를 바탕으로 작은 방향 시안을 제안한다. 생성 이미지가 필요하면 사용 가능한 이미지 생성 도구를 사용한다. 선택 후 필요한 해상도로 발전시킨다.
- 같은 실제 콘텐츠를 사용한 두 안의 PC·모바일 첫 화면과 다음 섹션을 보여준다. 섞기·직접 수정도 받는다. 제공된 완성 디자인을 그대로 구현하라는 요청이면 그 디자인을 기준으로 미리보기를 만든다.
- 원본 비율, 이미지 안의 글자, 로고·인물의 정체성을 보존한다. 사진은 얼굴 면적과 프레임을 맞추고 로고는 눈에 보이는 크기·여백·배경 대비를 맞춘다.
- 명단은 이름·역할·소속·순서·매칭을 확인한다. 자료가 상충하면 출처와 다른 값을 보여주고 중요한 값은 결정받는다. 최신 파일이라는 이유로 과거의 명시적 예외를 덮어쓰지 않는다.
- 전체 페이지 구축에는 현재 환경의 사이트 제작 도구·스킬과 기존 저장소를 활용한다. 게시 환경의 최신 절차는 해당 도구 지침으로 확인한다. 이 사례의 호스팅 계정·사이트 ID·색상·레이아웃을 새 프로젝트의 필수값으로 사용하지 않는다.
- [후속 카드와 검수](references/updates-and-checks.md)는 필요한 기능과 변경에 맞춰 읽는다. [AX 요청 대조표](references/ax-request-map.md)는 실제 요청에서 온 설계 근거를 확인할 때 읽는다.

## 저장과 재개

프로젝트 루트에 LANDING-PROGRESS.md를 저장한다. 작업 폴더가 아직 없으면 먼저 폴더를 정하고 기록한다. [진행 기록 양식](references/progress-template.md)을 사용해 자료의 출처·버전, 현재 단계, 확정값, 시안 선택, 미확정값, 자산 위치, 미리보기와 게시 상태를 갱신한다. 비밀번호·토큰·불필요한 개인정보는 기록하지 않는다.

새 채팅이나 후속 수정에서는 진행 기록과 실제 파일·게시 상태를 먼저 확인한다. 변경된 카드로 바로 이동한다. 수정 영향이 있는 메뉴·본문·번역·다른 자산 사용처까지 점검한다. 승인된 기존 선택은 재사용하고 사용자가 변경할 수 있게 한다.

## 공개와 인계

공유 범위와 대상 사이트가 이미 승인됐다면 그 승인을 재사용한다. 처음 공개하거나 대상을 바꿀 때는 구체적인 미리보기와 게시 대상을 제시한 뒤 필요한 결정을 받는다. 게시 전후 실제 URL, 접근 범위, 대표 신청 버튼의 최종 목적지, 이미지 로딩과 모바일 화면을 확인한다. 로컬 완료·업로드 완료·운영 URL 확인을 구분해 기록한다.

완료 응답에는 실제 결과 주소, 사용자가 선택한 주요 방향, 남은 미확정 항목과 확인하지 못한 사항을 짧게 적는다. 게시 실패 시 재시도·진단할 수 있는 범위까지 수행하고 마지막 성공 버전과 구체적인 장애를 남긴다.
