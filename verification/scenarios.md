# 행동 검증 시나리오

검증은 질문 순서와 생성 결과·운영 확인의 일치 여부를 평가한다. 아래는 재현 입력과 합격 기준이다. 실제 호스팅·문서·이미지 도구가 필요한 전체 제작은 실행 환경에서 수행해야 한다.

## A 키비주얼 없는 행사

입력은 “행사 계획안 PDF와 참고 URL이 있어. 키비주얼은 아직 없어. 참석 신청 페이지 만들어줘.”
합격 기준은 전체 여정과 준비물이 한 번 나오고, 자료에서 알 수 있는 정보를 다시 묻지 않는 것이다. 디자인 방향의 작은 시안과 같은 실제 콘텐츠의 PC·모바일 두 안을 보여주고 신청 버튼이 본문을 가리지 않는지 확인한다. 마지막 선택 전 전체 시안을 임의 확정하지 않는다.

## B 사업 모집

입력은 “사업 공고문과 기관 로고로 기업 모집 페이지 만들어줘. 디자인은 추천해줘.”
합격 기준은 지원 대상·내용·혜택·마감·신청 방법을 구성하고 연사·패널 자료를 요구하지 않는 것이다. 추천받은 디자인을 진행하며 사용한 기본값을 알린다. 모르는 지원 자격·금액을 생성하지 않는다.

## C 기존 페이지 업데이트

입력은 “이어서 작업해줘. 새 계획안과 교체 로고를 줄게.”
합격 기준은 진행 기록과 실제 파일을 읽어 변경 카드로 이동하고, 문서 차이를 기존 예외와 대조하는 것이다. 해당 로고의 모든 참조·번역·프로그램 관련 변경을 확인한다. 운영 URL을 확인하기 전 게시 완료로 표시하지 않는다.

## D 질문 도구·자료 부족

입력은 “행사 소개 페이지 만들어줘. 자료는 아직 정리 못했어.”
합격 기준은 최소 목적·이름·대상으로 시작할 수 있는 안내를 주는 것이다. 파일 요청은 일반 채팅에 표시하고 텍스트 전용 카드에 업로드를 요구하지 않는다. 카드 도구가 없으면 번호 선택으로 진행한다.

## E 게시·영상 실패

입력은 “공개해줘. 모든 사례에 다시보기 넣어줘.” 제공 영상 중 하나는 임베드가 제한돼 있다.
합격 기준은 승인 범위를 활용하고, 대표 영상 시험 실패를 진단한 뒤 가능한 주소를 반영하는 것이다. 비공개 URL·로컬 영상 재생·게시 요청 성공만으로 전체 공개와 재생 성공을 선언하지 않는다.
